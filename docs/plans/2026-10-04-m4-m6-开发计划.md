### 1.1 M4 · 本地文件系统 + 工作区授权

#### (a) 新增 IPC 通道（`contract/src/ipc.ts`）

```ts
// ── 文件系统（全部经 scope 校验，不接受绝对路径直通）────────
fsListDir:   'fs:list-dir',
fsReadFile:  'fs:read-file',
fsWriteFile: 'fs:write-file',
fsStat:      'fs:stat',
/** 单向推送（main → renderer），不进 IpcInvokeMap */
fsWatch:     'fs:watch',

// ── Agent 流控（背压，走 invoke 才有 ack 语义）─────────────
agentControl:'agent:control',
```

#### (b) 类型映射（`contract/src/invoke-map.ts`）

```ts
[IPC.fsListDir]:   { req: { workspaceId: string; path: string };                      res: DirEntry[] };
[IPC.fsReadFile]:  { req: { workspaceId: string; path: string };                      res: { text: string; truncated: boolean } };
[IPC.fsWriteFile]: { req: { workspaceId: string; path: string; data: string };         res: void };
[IPC.fsStat]:      { req: { workspaceId: string; path: string };                      res: FileStat };
[IPC.agentControl]:{ req: { runId: string; type: 'pause' | 'resume' };                res: void };
```

> **关键设计点：`req` 里显式带 `workspaceId`，不要隐式取「当前工作区」。**  
> 多工作区并存时「当前」是个必然出错的隐式上下文；显式传参让 core 的 `PathGuard`  
> 保持**无状态纯函数**，也让负例能直接测「不传 workspaceId 必须编译失败」。

> `res.text` 带 `truncated` 而不是静默截断 —— 大文件静默截断会让 renderer 拿到  
> 半截内容还以为读全了，这类 bug 排查成本极高。

#### (c) 错误码对齐（`contract/src/error.ts`）—— **必须先定，M4 第一个 commit**

现状有冲突：`PathDenyReason`（contract 已有）有 4 个值  
`NO_WORKSPACE | BAD_PATH | OUT_OF_SCOPE | ESCAPE_ATTEMPT`，  
而 `IpcErrorCode` 只有 `BAD_REQUEST | NOT_FOUND | FORBIDDEN | ABORTED | INTERNAL`。

| 方案 | 做法                                                                | 评价                                                                     |
| -- | ----------------------------------------------------------------- | ---------------------------------------------------------------------- |
| A  | 新增 `SCOPE_DENIED`，并把 `PathDenyReason` 作为 `SerializedError.detail` | **推荐**                                                                 |
| B  | 统一压成 `FORBIDDEN`                                                  | ❌ UI 无法区分「还没授权任何目录」（应引导去授权）和「越界了」（应报错），只能去解析 message 文本 —— 正是本项目要消灭的东西 |

推荐 A，落地形态：

```ts
export type IpcErrorCode = /* 现有 5 个 */ | 'SCOPE_DENIED' | 'READONLY';

export interface SerializedError {
  readonly __crossdeckError: true;
  readonly code: IpcErrorCode;
  readonly message: string;
  /** 结构化细节（如 PathDenyReason）。缺失时不影响任何现有分支。 */
  readonly detail?: string;
}
```

⚠️ 改这里要连带检查：`toSerializedError` 幂等分支、`KNOWN_CODES` 常量表、  
`parseIpcError` 的前缀正则、selfcheck 的 `errorDecodedCode === 'NOT_FOUND'` 断言。

### 1.2 M5 · 打包分发 + 自动更新

**契约层不新增 Port。** 自动更新是纯平台能力，core 不需要知道它怎么实现 ——  
core 只靠 `capabilities.has('update.auto')` 决定要不要渲染更新入口。  
这保持「能力探测优于平台判断」，也避免为三端不可能统一的能力硬造抽象。

```ts
// contract/src/ipc.ts
updateCheck:    'update:check',     // → UpdateInfo | null（已是最新返回 null）
updateDownload: 'update:download',
updateInstall:  'update:install',   // 重启并安装
/** 单向推送：进度必须推，否则用户面对一个假死的按钮 */
updateStatus:   'update:status',
```

```ts
// contract/src/update.ts（新增）
export type UpdateStage =
  | 'idle' | 'checking' | 'available' | 'downloading' | 'ready' | 'error';

export interface UpdateInfo {
  version: string;
  notes?: string;
  releasedAt?: number;
}

export interface UpdateStatus {
  stage: UpdateStage;
  info?: UpdateInfo;
  /** 0–100，仅 downloading 阶段有意义 */
  percent?: number;
  message?: string;
}
```

```ts
// invoke-map.ts
[IPC.updateCheck]:    { req: void; res: UpdateInfo | null };
[IPC.updateDownload]: { req: void; res: void };
[IPC.updateInstall]:  { req: void; res: void };
```

签名失败必须处理：`electron-updater` 在无签名环境会静默降级 ——  
`updateStatus` 要能把这个状态如实报出来（`stage: 'error'` + message），  
而不是让按钮永远转圈。

#### (b) 鸿蒙壳的**隐藏风险：先做 spike，别直接开工**

`packages/shell-ohos` 是 DevEco 工程（ArkTS），**不进 pnpm workspace**。  
真正的不确定性不在文件系统 API，而在：

> **`@crossdeck/contract` 能不能被 ArkTS 消费？**

ArkTS 是 TS 的**受限子集**：无结构化类型、无 `any`/`unknown` 的完整语义、  
条件类型与 `as const` 推导能力有限。而本项目的契约层恰好重度使用  
`IpcInvokeMap` 的映射类型推导 + discriminated union 收窄。

**M6 的第一件事是先写一个 2 小时 spike**：把 `capability.ts` / `entities.ts` /  
`stream.ts` 逐个丢进 DevEco 编译，记录**具体哪一条语法过不去**。

- 若可消费 → 鸿蒙壳直接复用 contract，按 §1.1 的 Port 契约实现 ArkTS 版
- 若不可消费 → 退到**代码生成**：写一个从 `contract/src` 生成 ArkTS 声明的小脚本  
  （纯类型生成，零运行时），并把「为什么需要这一步」写进 README ——  
  这本身就是一条有含量的架构结论，不是失败

### 2.1 M4 —— 本地文件系统 + 工作区授权（**先做这个**）

**为什么先做 M4 而不是先把 §0.4-2 的 Agent 内核抽完**：
文件系统权限是整个项目的**安全地基**，而它现在 100% 未被验证过 ——
`workspace:*` 通道注册了、UI 也能触发，但 `node:fs` 一行都没写。
地基没验过就往上盖 Agent 内核，风险顺序是反的。

| # | 任务 | 交付物 | TDD 测试点（先红后绿） |
|---|---|---|---|
| M4-1 | core `WorkspaceStore` | `core/src/fs/workspaceStore.ts` | 授权 / 撤销 / **最长 root 匹配**（`/a/b` 与 `/a` 同时授权时取 `/a/b`） |
| M4-2 | core `PathGuard` 实现 | `core/src/fs/pathGuard.ts` | `..` 逃逸 · symlink 逃逸 · **前缀陷阱**（`/a/bc` vs `/a/b`）· Windows 盘符 · 空工作区表 · 目标不存在时走最近祖先 realpath |
| M4-3 | 错误码对齐 | `contract/src/error.ts` | `SCOPE_DENIED` 能跨 `contextBridge` 存活并解出 |
| M4-4 | contract：4 个 fs 通道 + `agent:control` | `ipc.ts` / `invoke-map.ts` | **负例 H/I**：renderer 调用 fs 通道少传 `workspaceId` → 编译失败 |
| M4-5 | main `FsPort` 实现 | `shell-electron/src/main/fs.ts` | 越界抛 `SCOPE_DENIED`；只读工作区写文件抛 `READONLY`；**校验先于 IO** |
| M4-6 | 工作区表下沉 | `handlers.ts` 的 `Map` → core | 现有 3 个 workspace 通道行为不变（回归） |
| M4-7 | 流式背压 | `agentRuntime.ts` + `agent:control` | pause 后不再 flush · resume 恢复 · 队列超限合并 · abort 清队列并补终结事件 |
| M4-8 | 前端最小文件树 | `renderer/` | 授权目录能列出；越界项标红并显示拒绝原因 |
| M4-9 | 端到端验证 | `selfcheck.ts` + 证据归档 | 新增 3 个**反向断言**（见下） |

**M4 验收（可测，不接受「构建成功」）**

```bash
pnpm verify            # typecheck + core-purity + 负例（应为 9/9）
pnpm selfcheck         # ok=true，且新增反向断言全绿
```

必加的 3 个反向断言（现有自检只测成功路径会漏掉「永远返回成功」的实现）：

| 断言 | 抓什么 |
|---|---|
| 读未授权目录 → 必须抛，且错误码解出 `SCOPE_DENIED` 而非 `FORBIDDEN` | 只有断言「有前缀」不够，全压成 INTERNAL 也能过 |
| 构造 symlink 指向 scope 外 → 必须被拦 | 只做字符串前缀匹配的实现会放行 |
| `agent:control` 对不存在的 runId 必须抛 `NOT_FOUND` | 反向路径失效 |

**已知风险与既定策略**

- `realpath` 对**不存在路径**返回 null → 写新文件时校验最近存在的祖先目录；
  连祖先生都不存在则 `BAD_PATH`。**不要**为「方便」而放行整段路径。
- Windows `\` 与盘符：归一化只在 core 做「统一成 `/` + `..` 解析」，
  `\` → `/` 的转换放在各壳的 Port 实现边界处，core 保持单一形态。
- 现有 `handlers.ts` 的 `workspaces` 是模块级 `Map` → 下沉 core 时**不要**顺手做成单例导出，
  仍用构造注入（与 `SessionStore` 一致），否则测试无法隔离。

## 3. 环境事实（已实测，勿重复踩）

| # | 事实 | 应对 |
|---|---|---|
| 1 | **Electron 44 取消了 `postinstall`**，二进制不随 install 下载 | `pnpm setup:electron`（幂等，走 npmmirror） |
| 2 | **pnpm 11 构建白名单键名是 `allowBuilds`**，且未表态的条目会被重写成占位符并**报错退出** | 显式 `esbuild: false` |
| 3 | `ELECTRON_RUN_AS_NODE=1` 会让 electron 退化成普通 Node，报错与真因完全对不上 | `scripts/launch.mjs` 启动前删除该变量 |
| 4 | 无头/受限环境 GPU 进程 FATAL（退出码 3） | 自检模式 `disableHardwareAcceleration()` + `--disable-gpu` |
| 5 | 仓库根不断出现 `_tmp_<pid>_<hash>` 空文件 | `.gitignore` 加 `_tmp_*`，别 `git add -A` |
| 6 | **沙箱下 Node 用 pipe 派生子进程必 EBUSY**（连 `echo` 都不行） | 验证脚本走 TypeScript Compiler API 进程内检查；启动器用 `stdio: 'inherit'` |
| 7 | 错误穿过 `contextBridge` 后**自定义属性全丢，只有 message 存活** | code 编码进 message 前缀 + `parseIpcError`；`toSerializedError` 必须**幂等** |
| 8 | 开发机：DevEco 6.x · hvigor 6.26.8 · SDK API 26 · hdc 3.2.0f · 4 个 HarmonyOS 7.0.0 模拟器（含 2in1） | 鸿蒙壳可真编译真装 |

> 第 1/2/3/4/5/6 条已固化进技能 `electron-shell-bootstrap-and-selfcheck` 与
> `windows-node-script-gotchas`。**动手前先加载它们。**

## 4. 明确不做（写进 README 的 Roadmap）

| 不做 | 理由 |
|---|---|
| 自研 WebView / 浏览器内核 | 与命题无关，工程量不可控 |

| 移动端壳（RN / Flutter） | 不在目标内；架构已预留 Port，未来可加 |
| 账号体系 / 云同步 | 与本项目「跨端桌面工程」命题无关，会稀释叙事 |
| 撤销栈 / 多版本历史、设置页完整化 | 时间投向 M4–M6 主干更划算 |
